Короткий демонстрационный проект с простой системой спавна врагов волнами.
В проекте были использованы следующие плагины:
- Zenject (+ Signals)
- Dotween
- UniTask

Тип врага задается через ScriptableObject-ы в папке Assets\Configs\Enemies (из параметров в этом простом примере только спрайт и внутреннее название).
Настройки волн спавна конфигурируются в файле Assets\Configs\WavesConfig.asset.
Настройка волн имеет следующие параметры:
* DelayBefore - задержка перед стартом очередной волны, в секундах
* Enemy - тип врага (определяет спрайт, название)
* EnemyCount - число врагов в волне, спавнятся одновременно, в виде горизонтальной линии
* EnemySpacing - горизонтальный интервал, если EnemyCount указано больше 1
* Position - координаты спавна (если врагов больше 1, то эти координаты используются как центр)
* Target - координаты цели (враг исчезает по их достижению)
* ReachSteps - время, которое потребуется врагу, чтобы достиць целевых координат из исходной точки, в секундах (задает скорость перемещения)
* DelayAfter - задержка после завершения очередной волны, в секундах
* RepeatCount - если больше 0, то повторяет спавн врагов указанное количество раз
* DelayRepeat - если RepeatCount больше 0, то задержка между двумя повторами спавна данной волны (не применяется после финального повтора!)


Ответы на вопросы:

1. Как бы вы развивали эту систему, если типов врагов станет несколько десятков, а настраивать волны будет геймдизайнер без участия программиста?
- Упростить создание новых типов врагов, например, через Excel-таблицу и инструменты для её импорта/парсинга
- Добавить, по необходимости проекта, новые параметры для врагов: здоровье, урон, размеры, тип движения (вместо равномерного прямолинейного), звуки и пр., а также новые параметры для настройки волн
- Ввести ограничения/валидации на параметры (например, не допускать отрицательные числа для steps, незаполненные обязательные поля и т.п.)
- Написать удобные CustomInspector или визуализацию волны в OnDrawGizmos
- Геймдизайнеру может потребоваться настраивать каждому отдельному врагу в волне индивидуальное значение параметров здоровья/урона и т.п., спавнить в виде красивого паттерна или ритмично одного за другим

2. Что вы сделали бы иначе, будь у вас неделя вместо нескольких часов? Какие компромиссы приняли осознанно?
- Добавил бы нормальный способ указывать место спавна и цель, вместо явного указания чисел Vector2
- Не применял бы Dotween для перемещения врагов
- Переоценил, нужно ли глобально использовать Signals во всём проекте, не будет ли достаточно "обычных" событий
- Более полноценный, не минималистичный UI
- Для крупного проекта - обязательно выделение интерфейсов и использование их в качестве зависимостей вместо явного указания классов (для уменьшения связанности)
